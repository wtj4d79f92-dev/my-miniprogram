# 玩法图标位图（吉祥物）

金刚区的图标默认不是图片，而是画在 `utils/type-icons.js` 里的线性 SVG。这个目录放的是
**替换掉某几个类型的吉祥物位图**：一张图对应一个玩法。

## 命名与登记

```
assets/type-icons/<类型key>.jpg
```

- 类型 key 见 `utils/dict.js`（hiking / climbing / driving / camping / cycling / ball /
  pet / running / swimming / other）；
- 放好文件后到 `utils/type-icons.js` 的 `ICON_IMAGES` 加一行登记，`utils/dict.js` 会自动把它
  发给首页金刚区、广场类型面板、发布页类型网格三处（三处同源，改一处就全局生效）；
- 换图直接覆盖同名文件，不用动代码。

## 出图口径

- **尺寸 144×144，1:1**。金刚区格子 88rpx（约 44px），3 倍屏下就是 132px，144 留了一点余量；
  发布页格子 84rpx、广场面板里的徽标 36rpx，都在这张图覆盖范围内；
- **格式 JPEG（quality 84）+ 裁掉原图一圈留白**。原图是 2048×2048 的 PNG，裁掉边距后缩到
  144×144，单张 7–8KB。裁剪比例按每张的构图单独定（8%–14%）：吉祥物在画面里站得越靠后、
  底下留的道具越多，就越要多裁一圈，否则缩到 44px 会显小；
- **单张控制在 12KB 以内**：开发者工具的 `IMAGE_AND_AUDIO_LIMIT` 判定的是**全包图片加总**
  不超过 200KB（不是单张），现在 logo 48KB + 分享图 28KB，十个图标换完还有余量
  （`scripts/validate.js` 里有一条把总量钉住的检查）。

## 为什么放代码包，不放云存储

金刚区是首屏内容，图标走网络会先空一格再跳出来；海报那种「分享时才用到」的图才适合放云存储
（见 `utils/posters.js`）。代价就是上面那条 200KB 的预算，所以每张都要压。

## 关于底色

位图**自带底色**（暖色渐变，不是透明抠图），所以页面里是「铺满整格」——格子那层极浅品牌底被图片
完全盖住，不会出现「图一层底 + 格子一层底」的双层底色（见各页 `.type-icon-img.is-fill`）。

以后若要做成透明抠图，144×144 的 PNG 单张就要 30KB 以上，十个必然超预算，那种情况得改走云存储
（`posters/` 那套 fileID 取图的链路）。
